# AI Gateway: LiteLLM and copilot-api

Two services on `forge` give every AI client on the LAN one place to
authenticate and one place to pick a model. This page covers what they are,
how they fit together, the one-time bootstrap, and how to point clients at
them.

## Architecture

| Component | Deployment | Endpoint | Auth |
| --- | --- | --- | --- |
| LiteLLM | Podman container (factory module) | `https://llm.holthome.net` | Virtual keys (API), PocketID SSO (Admin UI) |
| copilot-api | Podman container (factory module) | `https://copilot.holthome.net` | Bearer client key managed by the module |
| PostgreSQL | Native, pgBackRest | internal | LiteLLM keys, spend, teams |

```text
Claude Code / SDKs / Open WebUI
        │ Anthropic or OpenAI protocol, virtual key
        ▼
   Caddy (llm.holthome.net, LAN only) ──► litellm:4000
        │ config.yaml model routes
        ├─ copilot/*      ──► host.containers.internal:4141 → copilot-api (client key)
        ├─ anthropic/*    ──► api.anthropic.com
        ├─ gemini/*       ──► Google AI Studio
        ├─ openai/*       ──► api.openai.com
        └─ <deployment>   ──► Azure AI Foundry

   Caddy (copilot.holthome.net, LAN only) ──► copilot-api:4141   (direct use)
```

copilot-api wraps the household GitHub Copilot subscription. It performs
GitHub's device-code login once, keeps the resulting OAuth token, and serves
Copilot's model catalogue over `/v1/messages` (Anthropic) and
`/v1/chat/completions`, `/v1/responses`, `/v1/embeddings` (OpenAI). Clients can
use it directly or through LiteLLM; LiteLLM is preferred because it adds
per-key budgets, spend tracking and a fallback to the direct providers when
Copilot is rate-limited or down.

Module headers hold the design detail:

- `modules/nixos/services/copilot-api/default.nix`
- `modules/nixos/services/litellm/default.nix`
- `hosts/forge/services/copilot-api.nix`, `hosts/forge/services/litellm.nix`

## First deploy: copilot-api login

The `podman-copilot-api` unit carries `ConditionFileNotEmpty` on the GitHub
token file, so it stays inactive (not failed) until the login has been done.
The `CopilotApiServiceDown` alert fires until then. On `forge`:

```bash
sudo copilot-api-login
```

The helper runs a throwaway container on the service's data directory and
prints a `https://github.com/login/device` URL plus a one-time code. Approve
it in a browser; the token lands in `/var/lib/copilot-api/data/github_token`
(0600, owned by the service user). Then:

```bash
sudo systemctl start podman-copilot-api
sudo journalctl -u podman-copilot-api -n 50
```

The startup log lists the model ids Copilot currently serves. The client key
every caller must present is generated by the `copilot-api-keys` oneshot:

```bash
sudo cat /var/lib/copilot-api/api-key
```

To manage keys in sops instead, create a secret with one key per line, add it
to `hosts/forge/secrets.nix`, and set `apiKeysFile` in the host file. LiteLLM
picks the first line up automatically through `extraCredentialFiles`.

## LiteLLM

Enabled on 2026-09-04 after being off since 2026-06-01, starting from a fresh
database. Reused from before: the `tank/services/litellm` dataset and the four
`litellm/*` sops secrets (`provider-keys`, `master_key`, `database_password`,
`oidc-client-secret`).

Changes from the 2025 definition:

- Factory-based module; the container, dataset, user, Caddy vhost, backup,
  preseed and notifications come from `lib/service-factory.nix`.
- Image moved from `litellm-database:main-stable` to the pinned
  `ghcr.io/berriai/litellm:v1.99.1`. Upstream now calls the `-database` image
  a legacy alias; the main image bundles Prisma and runs
  `prisma migrate deploy` on start.
- `config.yaml` is rendered into the Nix store with `os.environ/VAR`
  references. The old envsubst-at-runtime generator is gone; no secret is
  ever in the config file.
- Production defaults from the upstream checklist: `LITELLM_MODE=PRODUCTION`,
  JSON logs, `request_timeout: 600`, `proxy_batch_write_at: 60`,
  `disable_error_logs`, `database_connection_pool_limit: 10`.
- Provider wildcards (`anthropic/*`, `gemini/*`, `openai/*`, `copilot/*`)
  replace the pinned 2025 model list, plus `claude-opus`, `claude-sonnet`
  and `claude-haiku` aliases. Azure deployments stay explicit because an
  undeployed name 404s.
- The unused enterprise-only JWT API auth options were removed; Admin UI SSO
  through PocketID stays (free for up to five users).

Starting fresh: the `litellm` PostgreSQL database from the 2025 deployment
was dropped on forge on 2026-09-04 (it held the 36-table schema and no rows;
a safety dump is at `/var/lib/postgresql/litellm-pre-rebuild-20260904-102943.sql.gz`).
The `litellm` role was kept and `postgresql-provision-databases` recreates the
database on the next switch, so the new salt key never meets old ciphertext.
If you ever need to repeat this:

```bash
sudo systemctl stop podman-litellm
sudo -u postgres dropdb litellm
sudo systemctl restart postgresql-provision-databases
sudo systemctl start podman-litellm
```

The old module's leftovers on the dataset (`config/config.yaml` with
plaintext provider keys, the superseded `master-key`, and root-owned `.cache`
and `.npm`) were removed the same day; the new module only creates `data/`
and `secrets/` there.

Things that are deliberately unchanged:

- `LITELLM_SALT_KEY` is now set: generated once into
  `/var/lib/litellm/secrets/salt-key` (root, 0600, on the backed-up dataset)
  or taken from `saltKeyFile` if you move it into sops. It encrypts the
  credentials LiteLLM copies into the database and can never be rotated, so
  start from a clean database (below) rather than the 2025 one.
- `/metrics` is not scraped. It requires a LiteLLM key since v1.85, which the
  factory scraper cannot present. Enable it later with
  `litellm_settings.callbacks = ["prometheus"]` and an authenticated scrape.

### Model routes

| Request model | Goes to |
| --- | --- |
| `copilot/<id>` | copilot-api, Anthropic path (Claude models in the Copilot catalogue) |
| `copilot-oai/<id>` | copilot-api, OpenAI chat path (`gpt-*`, `o*`) |
| `anthropic/<id>`, `claude-opus`, `claude-sonnet`, `claude-haiku` | Anthropic API |
| `gemini/<id>` | Google AI Studio |
| `openai/<id>` | OpenAI API |
| `gpt-4o`, `gpt-5*`, `o3-mini`, `text-embedding-3-small` | Azure AI Foundry deployments |

`GET https://copilot.holthome.net/v1/models` (with the client key) lists the
ids Copilot serves today; prefix one with `copilot/` for LiteLLM.

### Pointing clients at it

Create a virtual key in the Admin UI (`https://llm.holthome.net/ui`, sign in
with PocketID) and give it a budget. Then:

```bash
# Claude Code
export ANTHROPIC_BASE_URL=https://llm.holthome.net
export ANTHROPIC_AUTH_TOKEN=sk-...            # the virtual key
export ANTHROPIC_MODEL=copilot/claude-sonnet-4.5

# OpenAI-compatible SDKs
OPENAI_BASE_URL=https://llm.holthome.net/v1  OPENAI_API_KEY=sk-...
```

To bypass LiteLLM and talk to copilot-api directly, use
`ANTHROPIC_BASE_URL=https://copilot.holthome.net` with the copilot-api client
key and a bare model id.

## Exposure and caveats

- Both containers publish on `127.0.0.1` only. Caddy serves them on LAN
  addresses; neither vhost is in the Cloudflare tunnel.
- copilot-api's `/usage-viewer*` and `/admin*` are answered with 404 at Caddy,
  so the admin surface is reachable only from `forge`.
- This is unsupported use of a Copilot subscription. Upstream warns that
  "excessive automated or scripted use of Copilot may trigger GitHub's
  abuse-detection systems". Keep the direct-provider routes in LiteLLM as the
  fallback.
- If the GitHub token is revoked, copilot-api fails at startup and restarts
  until the start limit; rerun `sudo copilot-api-login`.

## Operations

```bash
# Health
curl -s http://127.0.0.1:4141/                       # "Server running"
curl -s http://127.0.0.1:4100/health/liveliness

# Logs
journalctl -u podman-copilot-api -u copilot-api-keys -n 100
journalctl -u podman-litellm -u litellm-env -n 100

# Rotate the generated keys (services regenerate on next start)
sudo rm /var/lib/copilot-api/api-key && sudo systemctl restart podman-copilot-api podman-litellm
```

Backups: both datasets are snapshotted, replicated and restic-backed
(`standard` protection class, `allowEmptyBootstrap = true`). LiteLLM's real
state is the PostgreSQL database, covered by pgBackRest.
